## 二、本地编辑器：obsidian

本身以“库“的概念设计的一款 markdown 编辑器，非常适合存放结构性的文章集，个人认为是博客本地编辑的不二之选。

### 1. 基本编辑

##### markdown 语法简介

markdown 具有两个巨大优势：1. 纯文本文件；2. 格式简洁，可以更方便人专注于内容本身。

由于 markdown 是一种轻量级标记语言，因此 markdown 兼容 html 的所有标签，如果真的想要一些临时的花里胡哨的效果（比如着色文字），可以使用 html 标签解决，具体语法请自行搜索，在此不详细展开。除此之外，markdown 只需要以下几个标记就足以清楚地完成一篇文章：

+ 标题：在文字前方添加若干个 `#` ，`#` 的数量越多代表该标题层级越小。markdown 渲染器会自动为不同层级的标题渲染不同的样式。
+ 代码块：使用反引号 `` ` `` 包括行内内嵌的代码内容，如果引用的代码内容本身就包含反引号 `` ` ``，则使用双反引号 `` ` ` `` 包裹内容，并且内容前后与引号之间一定要有空格。对于代码块，使用三反引号，第一行三反引号后可以标注使用的代码语言。
+ 斜体：将内容用一对 `*` 包裹。
+ 粗体：将内容用两对 `*` 包裹。
+ 引用块：在整个文段前添加 `>`。严格换行符（连续的两个换行符）一定会打破引用块。
+ 无序列表：每项条目前添加 `+` 或者 `-`。
+ 有序列表：使用数字后紧跟一个 `.` ，会自动渲染为有序列表。
+ 转义字符：如果想要使用以上会被识别成样式/代码的符号，在符号前加一个 `\` 即可。

关于完整的 markdown 语法，可以参见官网[Markdown 基本语法 | Markdown 教程](https://markdown.com.cn/basic-syntax/)。

#### 可视化编辑/快捷编辑

如果希望有普通富文本编辑器的体验，可以安装第三方插件 `Editing Toolbar` 。它的样式实现依赖于 html 标签，因此即便是编译后，hexo 使用的 markdown 渲染器也可以保留样式。需要提醒的是，markdown 本身的初衷就是希望通过语义化统一管理样式，大量的个性化样式不仅会破坏阅读体验，还可能与站点的统一样式发生冲突，请自己取舍。

此外，对于中文作者，我推荐开启第三方插件 `Easy Typing`。这个插件提供大量中文符号的自动补全，并且将会自动将光标置于中间；可以完成自动的书面规范，包括统一增加或删去自然段落前的空格，英文首字母自动大写，以及英文字母、数字与中文汉字间自动空格；不需要手动切换中英文输入法，就可以在中文输入法下快速输入半角符号；样式、标题的快捷键。

### 2. 如何为博客建立一个 obsidian 的库

**个人配置：将 hexo 自动生成的 `source` 文件作为一个 obsidian 的库进行使用（打开本地仓库 - 选择 `source` 文件夹）。**

因为 hexo 的结构已经分为 `_drafts` 和 `_posts`，仅有 `_posts` 中的文章会被公开，因此在写作习惯上，理应是未完成的文章都存放在 `_drafts` 内进行编辑，而已完成的文章放入 `_posts` 。但是考虑到已经公开的文章也有需要修改的可能性，因此库中更推荐同时包含以上两个文件夹，方便编辑，也方便文章在不同文件夹之间移动。

### 3. 使用 git 进行多端编辑（以及后续托管）

虽然 obsidian 自身提供的多端同步服务是付费项目，但是作为一个具有丰富开源插件社区的软件，要同步 markdown 这种纯文本文件非常好自行解决：使用 git。目前官方的配置文件实际上也已经针对 git 做了优化（以前的 `workspace.json` 在不同的设备上操作必定冲突，尤其是跨平台时，现在移动端和 pc 端已经改为用不同的字段记录工作区，因此解决了这个问题）。

对于习惯使用命令行操作 git 的用户来说，应该无需赘述；不过既然是无痛全自动工作流，自然是能将 git 操作集成进编辑器最好。

对于没有使用过 git 的用户，首先需要在电脑上安装 git，并为每一个使用 git 的设备生成一个 SSH key 以进行身份认证。关于 git 的安装，可以参考[Git 详细安装教程（详解 Git 安装过程的每一个步骤）](https://blog.csdn.net/mukes/article/details/115693833)。关于 SSH key 生成与使用，可以参考[Github配置ssh key的步骤（大白话+包含原理解释）](https://blog.csdn.net/weixin_42310154/article/details/118340458)。注意每台设备都需要自己独立的密钥，因此如果有多端协同工作，需要都走一遍这个流程。特别地，移动端的配置更复杂，如果实在想要在工作流中包含移动端，不怕折腾的话可以跳转到文末阅读[类 Android 设备如何使用 git]。

另外，有一些关于 git 的使用基本注意事项：git 本身是为纯文本文件服务的，它能在每次不同的提交中对比出纯文本文件的具体变化内容，但是对于二进制文件只能标识出文件是否变化（如文件大小、文件名字），并且无法管理过大的二进制文件（需要使用 git lfs），所以不要往博客里塞过多无用的、大体积的二进制文件。

安装 git 后，还需要建立自己的本地仓库和远端仓库，并把它们关联起来。其实 git 代码托管平台很多，并不是只有 github，国内也有 gitee 以及阿里云，不过因为懒，本文只讲 github。

[官网](github.com)连接不稳定时好时坏跟 steam 商店差不多，需要魔法或者加速器（steam++ 有提供 github 加速服务，但有时候 dns 污染会导致加速了页面却不能进行推拉操作，需要关闭加速重新尝试）。

登录后左侧展示个人 dashboard，绿绿的按钮 `new` 就是新建远端仓库。仅需填写 repository name（自己取名或者就叫 my-blog 都行），description 选填。choose visibility 一栏保持 Public，因为之后我们要使用 github pages，只有保持公开的仓库才能部署到 github pages 上。其他的选项强烈建议不要动，因为本地通过 hexo 命令创建项目后自带 `.gitignore`，配置过后将本地代码推送到远端时可能会出现冲突。liscence 和 readme 实在想加可以加，但对于一个使用脚手架生成的博客项目来说没什么必要。

![新建仓库界面](IMG-20250916181041717.png)

初始化本地仓库用命令行比较快，复制 github 提供的模板内容，在 hexo 项目的根目录文件夹内右键-在终端中打开，然后在黑窗口中直接粘贴回车等待执行完毕即可。

如果不是 win 11，可以在文件夹上方的地址栏内输入 `cmd` 或者 `powershell` 然后回车，弹出来的那个也是终端，一样复制进去等待执行完毕即可。

![初始化本地仓库并关联到远程](IMG-20250916181400616.png)

要启用第三方插件，首先需要在设置 - 第三方插件中关闭安全模式，然后在市场中搜索 `obsidian git`，下载并安装。由于所有的插件都是发布在 github 上的，直连可能会无法加载，建议自行使用魔法，或者搜索国内搬运的插件库。

在 Automatic - Valut backup interval (Minutes) 处可以设置自动同步到 git 的时间间隔。如果使用自动上传的设置，建议同时打开 Auto Backup after stopping editing any file 设置，这样可以保证当你完成编辑时还有一次自动同步，不用怕没到下一次保存节点。

对于对 work tree 有点洁癖的人来说，可能更希望自己手动控制 commit 和推送，也很简单，使用 <kbd>Ctrl</kbd>+<kbd>P</kbd> 呼出命令面板就可以看到 commit、push、pull 操作，也可以到快捷键面板各自绑个快捷键。
